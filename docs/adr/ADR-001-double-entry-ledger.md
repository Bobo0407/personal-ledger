# ADR-001：複式記帳帳本

- 狀態：已採用（P1）
- 相關：規格第 5、6 節；決策 D1、D3、Q5、Q10

## 背景

原本的 Excel／VBA 記帳是單式流水帳：一筆支出只記「花了多少」，信用卡繳款、轉帳、退款很容易重複計入支出，
帳戶餘額也要另外維護，時間一久就對不起來。這個系統要長期使用，帳必須能自己驗證自己。

## 決定

1. **交易表頭 + 多筆分錄。** `transactions` 只放日期、類型、商家、付款方式等描述資訊；
   所有金額都在 `postings`，`postings` 是金額的唯一來源。
2. **帶正負號的金額：借方為正、貸方為負。** 一筆交易的分錄加總必須為 0（V02），且至少兩筆。
   不另外存「借／貸」欄位，加總、檢查都只要 `SUM(amount)`。
3. **金額一律是整數（新台幣元）**，資料庫欄位為 INTEGER；外幣另存 `original_currency` +
   `original_amount_minor`（原幣最小單位），只作紀錄，帳務一律以台幣分錄計算。
4. **餘額不儲存。** 帳戶餘額、期間合計、淨資產都由有效分錄即時加總（見 ADR-002）。
   查詢回傳「正常餘額方向」：資產、費用 = +SUM；負債、權益、收入 = −SUM。
5. **只有最末層科目可以記帳**（V03）；最末層 = 沒有任何子科目，不論子科目是否啟用（D3）。
6. 使用者介面不出現借貸：各種交易表單由 EntryBuilder 轉成平衡的分錄（見 ADR-003）。

## 考慮過的替代方案

- **單式流水帳 + 類別**：實作最簡單，但信用卡繳款、轉帳、退款都要靠特例處理，正是想離開 Excel 的原因。
- **分開的 debit／credit 欄位**：比較接近會計課本，但每個查詢都要處理兩欄，容易寫錯方向。
- **儲存餘額欄位**：查詢快，但每次修改、刪除、還原都要同步更新，一旦漏掉就和分錄不一致。
  個人帳的資料量很小，即時加總的成本可以忽略。

## 後果

- 正面：帳可以自我驗證（integrity.check_all() 檢查不平衡交易）；修改、刪除、還原後餘額自動正確。
- 正面：信用卡繳款只是負債減少、資產減少，自然不會計入支出（T03）。
- 代價：寫入時一定要經過 builder 和驗證，不能直接 INSERT 一筆「支出」。
- 代價：報表都是加總查詢；資料量很大時才需要考慮快取，V1 不做。
